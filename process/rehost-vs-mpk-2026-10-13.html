Answer · 2026-10-13 · Rehost vs MPK

How quick is module → MDL → module, and how does it compare with an MPK move?

The machine step takes seconds to minutes. It works cleanly on small, same-version apps with standard features. It breaks on Java actions, rules, legacy widgets, native layouts, recursion and 9.x authoring. For moving modules between apps, an MPK package is faster and keeps IDs.

The answer

How quick fast

Seconds to minutes, for the machine step only. A 155-document app took 35 s end to end. A 36-module app took about 36 min.

Review, repair and test time is on top and is not measured here.

Works cleanly when proven

The app is small, source and target are the same Mendix version, and it uses standard features. Banking: 154 of 155 documents identical, mx check 0 errors, build succeeded.

Breaks on limits

Java actions with type parameters, rules, legacy widgets, native layouts, mutual recursion, and Mendix 9.x authoring. The 48-module GenAI app: 29 of 36 modules landed, build failed with 14 errors.

Terms, once

  • MDL is Mendix's text language for describing a model: entities, microflows, pages.
  • mxcli is the command-line tool that reads and writes MDL against a .mpr project.
  • describe turns a model document into MDL text. exec runs MDL text and writes the document into a project.
  • MPK is Mendix's own module package: a zip with the module's model units plus its Java, theme and widget files.
  • Rehost is regenerating a module (or app) through MDL into a fresh project.

1. How Rehost works

Four steps. No person and no AI authors anything in this step. It is a machine round trip: the model describes itself, and the text is written back.

  1. Describe each module to MDL textPer module, plus every document type the whole-module describe leaves out (nanoflows, snippets, mappings and others), one by one.
  2. Checkmxcli check validates the text. It is all-or-nothing per file, so rejected statements are quarantined and the rest goes on.
  3. Write into a fresh projectRepair loop: check, quarantine, exec, resume. A statement that fails is deferred with its error; the rest continues. Deferred statements retry in passes.
  4. Describe the target and compareThe target is described again and every document is compared with the source. The result is the fidelity ledger: identical, drift, failed, not emitted, not expressible.

5. How to use it in practice

  1. Rehost (MDL)A clean re-platform of a small to medium app, an audit or inventory of a model as text, or regenerating parts of an app.
  2. MPKMoving modules between apps (Decompose), keeping data and IDs.
  3. HybridMPK to move, MDL for the edges and the seams.

What a Rehost does not carry

  • Passwords and demo-user secrets (described as a masked value).
  • Per-environment constant values, certificates and database credentials. Constants themselves are copied, with their default values.
  • Navigation: the extractor does not emit it, so it is re-entered.
  • The theme.
  • Project security level (described as a report, not MDL).
  • Environment configuration.

Run the same journeys against source and target afterwards. Identical describe output does not prove identical behaviour. The Banking run was proven statically only: mx check, build and describe compare.

6. Why MDL is valuable even without a rebuild

Describing an app as MDL text is useful on its own. Reading and comparing do not need the text to be re-executable, so the round-trip limits above do not apply here.

Rule of thumb: describe every app you touch, even when you move it by MPK. The text costs seconds to minutes and pays back in understanding, review and test scoping.
