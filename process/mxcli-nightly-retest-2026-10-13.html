Follow-up to #1437 (U44), drafted, not filed.

Title: run --local on a Mendix 9.24 app now builds with JDK 17 but the runtime launcher requires Java 11 and exits

The fix makes a Mendix 9.x project default to JDK 17, which removes the Gradle Unsupported class file major version 65 failure in mxbuild. The runtime that mxcli then starts for 9.24.2 refuses JDK 17. A JAVA_HOME pointing at JDK 11 is ignored, and run --help has no --java-home option. Reproduced on a blank 9.24.2 app made with mxcli new --version 9.24.2. Error verbatim:

Incompatible java version: 17.0.20.1 … Java 11 is required

7. How to read this, and what we did not do

  • Verdicts for the first batch (50 items) came from automated retests: each issue's own reproduction re-run on the nightly. 7 of the 15 fixed items (U5, U14, U16, U22, U29, U34, U37) were then re-verified by hand. The other verdicts were not re-checked by hand, apart from the four judged in Table 2.
  • The later runs (U54 to U74) were drafted and retested on both v0.26.0 and the nightly on fresh blank apps.
  • The nightly is not a release. It is a build of main on 2026-10-13, and later commits may change any row.
  • Fixed means the reproduction in our report no longer fails. We did not test other shapes of the same defect.
  • Nothing has been filed by us. The drafts exist; the issue numbers above are the ones already on mendixlabs/mxcli.
  • Test apps: blank apps created with mxcli new, the public FSM template, and the public GenAI Showcase App. No client data.
